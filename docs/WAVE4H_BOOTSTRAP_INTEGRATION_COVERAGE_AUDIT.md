# Wave 4H — Bootstrap Pipeline Integration Coverage Audit

**Candidate:** `.github/workflows/v2.7.2.4.2-bootstrap-pipeline-integration.yml`  
**Decision:** `NOT_READY`  
**Scope:** documentation-only coverage audit and preservation planning

## Executive conclusion

Current tests reproduce important in-memory bootstrap behavior, but they do not reproduce the complete historical GitHub Actions contract. The candidate is therefore not ready for a final preservation run, disablement, archival, relocation, rename, or deletion.

The workflow remains unchanged.

## Historical workflow contract

The workflow is manual-only and exposes three required inputs:

| Input | Default | Purpose |
|---|---:|---|
| `opportunity_limit` | `20` | Maximum opportunities generated by the fresh daily pipeline |
| `research_threshold` | `25` | Preliminary candidate eligibility threshold |
| `selection_limit` | `3` | Maximum candidates admitted to the bootstrap queue |

It configures:

- `BRAVE_API_KEY` from repository secrets;
- `BRAVE_MAX_REQUESTS_PER_RUN=4`;
- `BRAVE_CACHE_TTL_HOURS=24`;
- `EXTERNAL_RESEARCH_MAX_OPPORTUNITIES=0`;
- Python 3.11 and `PYTHONPATH` for the project package.

It creates `data/validation`, `data/investment_files`, and `data/evidence`, generates a fresh real dataset, synchronizes investment files, builds the research bootstrap report, prints the report when present, and uploads a 14-day artifact named `v2.7.2.4.2-bootstrap-pipeline-integration`.

The artifact boundary includes:

- `data/validation/`;
- `data/todays_opportunities.json`;
- `data/investment_files/`;
- `data/evidence/`;
- `data/brave_cache/`;
- `data/brave_usage.jsonl`.

Missing artifact files produce a warning through `if-no-files-found: warn`.

## Implementation behavior

`scripts/run_research_bootstrap.py`:

- accepts dataset, output, investment-files directory, threshold, and selection-limit arguments;
- reads and parses JSON from the dataset path;
- synchronizes investment files before queue execution;
- detects whether a Brave key is present without serializing the key into the report;
- creates `ResearchBootstrapPipeline` with the configured threshold and selection limit;
- writes a deterministic JSON report and prints the same report;
- returns success when those operations complete.

`ResearchBootstrapPipeline`:

- delegates preliminary scoring and deterministic candidate ordering to `PreliminaryResearchCandidateScorer`;
- creates a queue only from selected candidates;
- does not forward unselected candidates;
- preserves the queue but does not forward it when execution is disabled;
- records a reason for each non-forwarded candidate;
- isolates a single candidate failure so the remainder of the queue continues;
- records execution, evidence, comparable, buyer, scenario, completion, and error counts;
- preserves the final investment threshold as a separate concern.

## Important execution ambiguity

The workflow declares `EXTERNAL_RESEARCH_MAX_OPPORTUNITIES=0`, but the CLI creates an enabled `ResearchBootstrapPipeline` whenever a Brave key is present. The current focused tests prove explicit `enabled=False` behavior, but they do not prove how the real external loop interprets the zero environment limit during a complete workflow run.

This is not classified as a production defect in this documentation-only task. It is a required preservation-run verification point.

## Readiness decision

```text
NOT_READY
```

The current suite is insufficient to replace the historical workflow because unique live, file, secret, cache, usage, artifact, and GitHub Actions behavior remains uncovered.

## Rollback approach

No runtime change is authorized by this audit. A future reversible change must preserve the workflow at its current path and document:

1. the exact pre-change commit SHA;
2. restoration by reverting the change or restoring the complete workflow file from that SHA;
3. verification that `workflow_dispatch`, inputs, environment, commands, artifact name, paths, and retention are restored exactly;
4. a YAML validation and repository regression run after restoration.

Deletion remains unapproved.
