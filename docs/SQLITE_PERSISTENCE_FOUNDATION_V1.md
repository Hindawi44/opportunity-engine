# SQLite Persistence Foundation V1

## Purpose

This foundation adds durable state beneath the existing JSON reports without changing the discovery, scoring, ranking, Top 5, alert, or official decision pipelines.

JSON remains the operational report and interchange format. SQLite becomes the durable store for identities, latest snapshots, human-review tasks, status history, and pipeline-run history.

## Stack

- SQLite from the Python standard library
- SQLAlchemy 2.x as the repository and ORM boundary
- Alembic 1.x for versioned schema migrations

No database server, Docker service, PostgreSQL instance, or external API is required.

## Initial schema

### `opportunities`

Stores one stable `opportunity_id` and the latest copied snapshot:

- title and URL
- source and market code
- official `final_decision`
- `opportunity_score`
- complete source payload as JSON
- first-seen and last-seen timestamps

The repository copies official values. It does not recalculate them.

### `shipment_evidence_tasks`

Stores tasks generated by Shipment Evidence Workflow V1:

- stable `task_id`
- linked `opportunity_id`
- task type and requested fields
- Norwegian and Arabic questions
- priority and status
- blocking flags
- current value and evidence references
- complete task payload as JSON

A task cannot be saved before its opportunity exists.

### `status_history`

Append-only transitions for:

- opportunity decisions
- shipment-evidence task statuses

Repeated snapshots with the same status do not create duplicate transitions.

### `source_runs`

Stores pipeline/source runs, including valid zero-result runs. Zero results are data, not an implicit source failure.

## Repository boundary

Application code uses `OpportunityRepository`. It does not issue table-specific SQL from discovery or decision logic.

```text
Opportunity Engine
        ↓
OpportunityRepository
        ↓
SQLAlchemy
        ↓
SQLite
```

## Initialize a local database

```bash
PYTHONPATH=src python scripts/init_opportunity_database.py
```

Default location:

```text
data/opportunity_engine.db
```

Local database files are ignored by Git.

Use a custom database:

```bash
PYTHONPATH=src python scripts/init_opportunity_database.py \
  --database-url sqlite:////absolute/path/opportunity-engine.db
```

The command applies Alembic migrations and prints the active revision and tables.

## Migration policy

The initial revision is:

```text
0001_persistence_foundation_v1
```

Future schema changes must use new Alembic revisions. Do not delete and recreate a production database to add fields.

## Scope and safety

V1 does not:

- write to SQLite from P4 or scheduled workflows
- replace existing JSON reports
- alter `final_decision`
- alter scoring, ranking, Top 5, or alerts
- contact sellers or carriers
- calculate transport, tax, customs, or profitability
- create automatic purchase, bid, or approval actions

The next persistence step is a separate adapter that imports the current operational opportunity, shipment-evidence queue, and pipeline-run metadata through `OpportunityRepository`.
